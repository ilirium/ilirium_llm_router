# Branches — every one this repository has had

**Read it to place a branch in the project's history**: what it was for, when it opened, when it
landed, and which milestone and phase it belongs to. One line each, newest first.

**Five of its six columns are generated from git by `../procedures/branch-index.py`.** Only the last
one is written by a person. That split is the whole design and it is argued in
`../method/IDM-001-git-branching.md` — a hand-maintained list of merged branches was refused there,
correctly, because it drifts. A derived one cannot.

**Re-run the script at every merge — after the merge commit, never inside it.** Merge `--no-ff`,
then `python3 docs/procedures/branch-index.py --write`, then commit the table on the trunk. The new
row names the merge hash, so it cannot exist before the merge and amending the merge to hold it would
change the hash the row just recorded. `--check` exits 1 when the table no longer matches git, which
is the only thing standing between this file and the failure it was written to avoid.

## What this file is not

**It does not replace a phase note.** The permanent record of a phase — its plan, what it expected,
what it found, its evidence — is `milestone-N-*/phase-N-*/`, and each milestone's `README.md` reads
its own phases in order with a richer sentence than fits in a table cell. This is an index across all
of them, which is the one thing neither of those can be.

**It does not hold in-flight branches.** `IDM-001` gives those to `../status.md`, with the tree state
and the next action, and this file would be a second and staler home for the same thing. A row here
says what a branch *did*, which is not knowable until it is done. The script prints unmerged branches
as a note under the table rather than tabling them.

## Three things the table shows that no other document did

**There are three fast-forwarded branches, not two.** Every document that mentions this says *"Phases
0 and 1 were fast-forwarded"* — `../status.md`, `../milestone-1-core/README.md`, `IDM-001` — and each
is correct, because each is talking about *phases*. But `docs/add-claude-md` is a third, and it
predates Phase 0: five commits on 2026-07-27 that put the README, `CLAUDE.md`, the design decisions
and the first implementation plan into the repository. It appears in no document before this one.
Nothing was lost and nothing was mishandled; it simply belonged to no phase, and until `IDM-001`
gained its third row on 2026-08-21 a branch belonging to no phase had nowhere to be recorded.

**Nineteen branches, and eight of them carry no phase number.** Better than two in five is work
that is real, merged, and outside the phase sequence. That is the ratio behind `IDM-001`'s
"orthogonal" rule, and it is the argument against the reflex that a phase note is where branch
history lives: a scheme that only records phases would be missing eight of these rows.

**The two ends of the size range are both instructive.** `chore/tracked-allowlist-make-sync-and-clean`
is one commit; `feat/phase-10-body-store` is sixty-three across four days. Both were merged `--no-ff`,
which is why both are visible here at all.

## Why this is in `reference/`

**It is worth stating, because the tier's own admission test appears to refuse it.**
`README.md` asks: *would this fact still be true if the phase that found it had never happened?* — and
a table made of phases seems to answer no.

It passes on the second reading, which is the right one. The test asks whether a fact **depends on a
phase's plan, its ordering, or what it expected versus found** in order to be understood. These rows
do not: a branch's name, dates, hashes and purpose are true as read, from any distance, and they stay
true after the milestone closes and its folder stops being live. The alternative homes were both
worse — a milestone archive can only hold its own branches, and `../status.md` holds state, which this
deliberately is not.

The tier's other rule is the stronger argument: **one file per subject, each with a nameable trigger.**
The trigger here is exact — *you have a branch name, or a merge hash, and want to know what it was* —
and no other file answers it.
